# pair-wise-yy-59 法律文件披露、去密与发布质控工作台

用于诉讼披露批次中的区域去密、双人复核、密级管控与发布门禁。PDF.js 真实渲染示例文档，去密区域可绘制、确认并持久化到本地草稿。

## 统一授权依据（核心模型）

文档密级、去密区域、复核结论、发布批次**共用同一条授权依据（Basis，含版本号与区域指纹）**：

- **级联失效**：密级或去密区域一旦变化，依据版本 +1，相关文档的已接受复核结论立即失效，所有包含该文档的**未导出**批次条目「退回等待」；已完成导出与其他文档不受影响。
- **恢复机制**：文档重新基于当前依据完成规定签名（内部 1 签、机密/严格机密 2 签）且无草稿区域后，退回等待的批次条目自动携带新版本与新密级快照恢复待导出。
- **权限门禁**：查看、修改（密级/区域）、复核、导出按「角色 × 授权密级」校验；越权一律拒绝并写入授权审计账，正文与标题不呈现。
- **并发提交**：两名复核员同时提交同一文档时，先提交者占用当前依据；内容一致的后到提交作为会签接受，内容/区域不同则进入**待裁决账**，绝不覆盖已接受内容。裁决人不得是提交人；采纳即写入差异并升级依据，驳回则维持原结论。
- **导出检查点**：导出按文档逐个推进并记录检查点（completedDocIds）；失败（含故障注入与导出途中鉴权失败）后从检查点重试，已完成文档按 docId 去重，不会重复导出。
- **批次密级快照**：文档加入批次时固化密级快照与依据版本。历史批次缺少快照的文档**隔离待复核**，只能由有权限的复核员人工补录快照并留说明，**不得按今天的密级直接放行**。导出还校验批次内不得夹带无权文档。

### 建议演示路径

1. 林清打开 DOC-00418（严格机密）→ 拒绝查看并写审计；切顾言导出 BATCH-03 → 夹带拒绝。
2. 周叙在 DOC-00427 新增去密区 → 依据升级、双签复核失效、BATCH-02/03 中该条目退回等待，DOC-00435 照旧。
3. 周叙、沈律依次重新提交（理由一致会签）→ 条目自动恢复待导出。
4. 复核页：周叙先提交 DOC-00418，沈律附区域建议提交 → 进入待裁决账；周叙裁决采纳/驳回（可用「重置演示」后重复演示驳回）。
5. 发布批次页：高衡导出 BATCH-03，故障注入默认在 DOC-00427 中断一次 → 检查点重试，无重复文档。
6. BATCH-01 为历史批次（DOC-00418 无密级快照）→ 导出被拒并隔离；周叙「复核补录」后解除隔离（仍须完成复核才能导出）。

## 技术栈

React、Radix UI 风格组件、Zustand（含 persist）、TanStack Router、TanStack Query、PDF.js、Vite、TypeScript。

## 运行

```bash
npm install
npm run dev
```

访问 `http://localhost:62059`。示例 PDF 由浏览器端生成后交给 PDF.js 渲染，不需要外部文件。顶栏「重置演示」可恢复初始数据。

```bash
npm run build
```
